# Сверка с записями на доске и условиями практики

Проверено 21.11.2026 по фотографиям занятия, условиям от 08.09, 28.09, 13.10 и 23.10 и фактическим исходникам. При уточнениях используется более позднее условие. Это проверка соответствия, а не новый расчёт орбит или подтверждение сдачи.

## Первый этап

| Пункт | Состояние реализации |
|---|---|
| Начальные координаты и скорость, система dr/dt = v, dv/dt = a | Есть: State и Dynamics::operator() |
| Начало координат в Меркурии; вычитание ускорения Меркурия из барицентрического ускорения аппарата | Дифференциальное ньютоновское притяжение реализовано; полная релятивистская разность EIH отсутствует |
| Солнце, Луна, планеты | В Dynamics есть Солнце, Венера, Земля, Луна и системы Марса–Нептуна. Плутон из исходной таблицы GM не включён в динамику; в световых задержках он есть |
| Уравнения Эйнштейна–Инфельда–Хоффмана, члены с 1/c² | Не реализованы в динамике. Наличие релятивистской задержки света во втором этапе это не заменяет |
| Рунге–Кутта 8-го порядка | Не реализован: используется адаптивный Dormand–Prince 5(4) |
| Адамс–Башфорт–Моултон 13-го порядка на фотографии | Не реализован. На доске показан другой численный метод; в письменном условии 08.09 указан RK8. Нельзя утверждать, что текущий код содержит любой из этих двух методов |
| Шаг 1 минута | 60 с — сетка вывода. Внутренний шаг интегратора адаптивный, это не фиксированный шаг 60 с |
| JD 2455646.83, 20 часов | Есть; соответствует уточнению 13.10, заменившему первоначальные 1–2 суток и прежнюю эпоху |
| DE440t на фотографии, DE442t в письме | Используется de442t.bsp по письменному условию; замена на файл с доски не требуется |
| CSPICE, получение состояния из SPK | Есть: spkez_c с числовыми ID вместо spkezr_c со строковыми именами |
| Сравнение с msgr_final.bsp | Есть: траектория интегрируется из начального состояния, эталон читается отдельно для сравнения |
| Поле HgM009 до степени и порядка 160, радиус 2440 км | Есть; центральный член уже включён, повторно добавлять его нельзя |
| Предоставленный grav.cpp / SHTOOLS | Файлы сохранены, но рабочая программа использует собственный gravity.hpp. Полную эквивалентность степени 160 независимой проверкой не подтверждали |
| Матрица ориентации Меркурия из указанных работ | Используется готовая IAU_MERCURY из pck00010.tpc. Собственная формула по указанным работам отсутствует; согласованность ориентации с HgM009 требует проверки |
| GM | Для Меркурия используется GM из заголовка HgM009, для остальных тел — gm_de431.tpc; это не буквальное использование всей таблицы из первого условия |
| Солнечное давление | Правильно отключено по уточнению 23.10 |
| Ошибка положения и RMS | Есть: максимум 981.52 м, RMS 342.46 м, конечная ошибка 672.42 м в сохранённом расчёте |

Максимум около 982 м согласуется с ориентиром около 1000 м при учёте гармоник и без солнечного давления. Число 250–300 м в условии 13.10 относилось к добавлению солнечного давления, которое 23.10 отменили. Само совпадение максимума с ориентиром не подтверждает полноту динамики.

Первый этап нельзя считать полностью соответствующим исходному заданию, пока отсутствуют EIH и RK8. Отдельно требуется проверить ориентацию, состав возмущающих тел и согласованность GM. Изменение названий в документации не устраняет эти различия.

## Второй и третий этапы

Световое время, обе ветви Земля–аппарат–Земля, станции DSN, повороты через SOFA, EOP, поправки CIP и кубические сплайны реализованы. В опубликованной третьей копии используются MJD в TAI и разность TT−TDB из de442t. В старой второй копии остаются прежние соглашения времени; при проверке условий нужно различать эти версии.

В третьей копии реализованы двухсторонний доплер, коэффициент 880/749, интегрирование по ramp-таблицам, отбор type 12, миллисекунды для compression_time, порядок rx/tx и упаковка полей по условию 23.10.

Третий этап проверяет измерительную модель на эталонной SPK-орбите, а не на численно интегрированной траектории первого этапа. Поэтому его статистика не проверяет всю цепочку решения обратной задачи.

На доске написано RMS(Observed−Computed), видны значения 0.005 и 0.1 Гц. Контекст не позволяет уверенно объявить их окончательным критерием приёмки. В сохранённом полном расчёте третьей копии RMS = 0.17616 Гц после маркировки одного экстремального наблюдения; все 12832 строки сохранены, 12831 входит в основную статистику. Если критерием считать 0.1 Гц, он не достигнут. Для всех строк без исключения экстремума RMS существенно больше; это отдельно записано в summary.json.

Релятивистские задержки распространения света не означают наличие релятивистских уравнений движения.

## Обратная задача и локальная четвёртая копия

На фотографиях описана общая цепочка: начальное состояние → интегрированная траектория → модель доплера → невязки → МНК → поправка начального состояния.

Локально есть 04_stages_1_4: оцениваются шесть поправок начального состояния методом Левенберга–Марквардта. Подробного отдельного письменного условия четвёртого этапа в найденной переписке нет; общей постановке с доски такой выбор соответствует.

Однако локальная четвёртая копия содержит старые версии doppler.hpp и stations.hpp: compression_time * 0.01, прежний порядок tx/rx и EOP по UTC. Исправления опубликованной третьей копии в неё не перенесены. Её результат нельзя считать окончательной проверкой по актуальным условиям. Сохранённая проба охватывает 23 наблюдения за полчаса: RMS 0.05801 → 0.01863 Гц за одну итерацию, converged=false. Она не доказывает сходимость на всём наборе.

## Что нужно уметь объяснить на защите первого этапа

1. Что содержат r, v, a и State; почему нужны начальные координаты и скорости.
2. Чем задача движения относительно Меркурия отличается от барицентрической.
3. Зачем вычитается ускорение Меркурия и пересчитывается притяжение на траектории.
4. Что дают гармоники, зачем поворачивать координаты в систему планеты и ускорение обратно.
5. Что делает CSPICE и что самостоятельно рассчитывает интегратор.
6. Чем сетка вывода отличается от внутреннего шага.
7. Чем численная погрешность отличается от расхождения физических моделей.
8. Какие пункты исходного задания в текущей реализации отсутствуют.

Фотографии содержат частично закрытые формулы. Они пригодны для сверки тем и постановки, но не для восстановления всех коэффициентов EIH по неполным строкам. Для реализации нужны полная формула, проверка соглашений и отдельная валидация.
