# MESSENGER: моделирование орбиты и обработка наблюдений

Актуальная исправленная версия от 28.11.2026. Расчёты написаны на C++17, используются CSPICE и процедуры IAU SOFA. Python нужен для графиков, воспроизведения таблицы коэффициентов и независимой проверки поля.

## Структура

| Папка | Доступные расчёты |
|---|---|
| versions/01_stage_1 | orbit, selftest |
| versions/02_stages_1_2 | orbit, lighttime, selftest |
| versions/03_stages_1_3 | orbit, lighttime, doppler, selftest |
| versions/04_stages_1_4 | orbit, lighttime, doppler, fit, selftest |
| src | Канонические исходники полной версии |
| results/corrected | Результаты исправленной модели и проверки |

Все накопительные копии содержат исправления предыдущих этапов. Соответствие поддерживает tools/sync_versions.py. Отключённые этапы не включаются в сборку ранних копий.

## Запуск

Нужны Visual Studio 2022 с инструментами C++ x64 и CMake. Общие данные и библиотеки находятся в data и vendor. Файл config/mercury_orbit.txt входит в исходники и также нужен для запуска. При загрузке с GitHub распакуйте общий архив из Releases в корень репозитория.

Из папки MESSENGER:

```powershell
.\versions\01_stage_1\run.cmd
.\versions\02_stages_1_2\run.cmd
.\versions\03_stages_1_3\run.cmd
.\versions\04_stages_1_4\run.cmd
```

Скрипты собирают соответствующую копию и запускают orbit, lighttime, doppler или fit. build_versions.cmd собирает и проверяет все четыре копии. F5 в подготовленной рабочей области позволяет выбрать копию и режим.

Примеры после сборки:

```powershell
.\build\04_stages_1_4\Release\messenger.exe orbit --step 60 --hours 20
.\build\04_stages_1_4\Release\messenger.exe orbit --step 30 --out results/check_step30
.\build\04_stages_1_4\Release\messenger.exe lighttime --interval 300
.\build\04_stages_1_4\Release\messenger.exe doppler --trajectory reference
.\build\04_stages_1_4\Release\messenger.exe fit --points 180 --iterations 12
```

Параметр --out задаёт отдельную папку результатов. --step управляет шагом RK8 и по умолчанию равен 60 с. --interval задаёт сетку вывода орбиты и должен быть кратен шагу. --tol удалён, поскольку адаптивного интегратора больше нет.

## Этап 1

Проверка по замечаниям от 27.11: [требования, формулы, вызовы и результаты](STAGE_1_AUDIT.md). Матрицы поворота выписаны явно; амплитуды либрации вычисляются по Stark (3), без готовой таблицы отношений. Исходные физические параметры и их источники перечислены отдельно в MODEL_SOURCES.md.


Начало — JD 2455646.83 TDB, длительность — 20 часов. Начальное состояние и эталон берутся из msgr_final.bsp. Интегрируются координаты и скорости относительно Меркурия в осях J2000, в км и км/с.

Модель включает:
- центральное притяжение Меркурия;
- полностью нормированное поле HgM009 степени и порядка 160;
- Солнце, Венеру, Землю, Луну и планетные системы Марса–Плутона;
- полную точечно-массовую поправку EIH первого постньютоновского порядка, β = γ = 1;
- разность барицентрических ускорений аппарата и Меркурия;
- собственную матрицу ориентации Меркурия с прецессией и либрацией.

GM соответствуют таблице условия. Для Меркурия используется 22031.868551 км³/с², радиус поля — 2440 км. Заголовок SHA-файла не заменяет эти заданные параметры.

Интегратор — Dormand–Prince RK8 с 13 стадиями по указанной преподавателем таблице, основной шаг фиксирован: 60 с. За 20 часов выполняется 1200 шагов. Солнечное давление отключено по уточнению 23.10.

Сохранённый результат: максимум ошибки положения около 975.70 м, RMS 341.19 м, конечная ошибка 669.80 м. Ориентир 250–300 м относился к отменённому варианту с солнечным давлением.

Интерфейс shGravCreate / shGravLoadCoefficients / shGravCalculate использует AU и сутки, как в условии. В обычной сборке он работает через C++ backend, независимо проверенный с SHTOOLS. Исходные grav.cpp и grav.h сохранены в общих данных. Для установленного SHTOOLS предусмотрен флаг CMake MESSENGER_USE_SHTOOLS=ON. Эта дополнительная конфигурация требует заголовков, библиотеки и её зависимостей; стандартная сборка Fortran не требует.

Подробное объяснение: [DEFENSE_GUIDE.md](versions/01_stage_1/DEFENSE_GUIDE.md).

## Этап 2

Восходящая и нисходящая световые ветви решаются итерационно по Moyer 8-55, с γ = 1. Учитываются задержки всех одиннадцати массивных тел, включая солнечный член с поправкой на изгиб луча.

Положения станций читаются в ITRF2008, учитываются скорости станций, EOP и поправки CIP. Используются SOFA, эпохи EOP в TAI и эфемерида TT−TDB из de442t. EOP интерполируются натуральными кубическими сплайнами.

По умолчанию используется численно интегрированная орбита EIH/RK8. Между её узлами применяется натуральный кубический сплайн по рекомендованному пособию; подробная сверка — [STAGE_2_SOURCE_MAP.md](STAGE_2_SOURCE_MAP.md). Режим --trajectory reference отдельно проверяет световое время на эталонной SPK, интерполируемой кубическим сплайном.

Замыкание уравнения показывает численную сходимость решения; оно не является оценкой физической точности орбиты.

## Этап 3

Реализован ramped two-way Doppler по Moyer 13-54, M2 = 880/749. Фаза точно интегрируется по кусочно-линейным ramp-участкам с разбиением на границах.

Парсер следует текстовому условию 23.10:
- используются только строки type 12;
- compression_time умножается на 0.001 с;
- станции читаются в порядке rx, tx;
- REF = (high·2²⁴ + low)/1000;
- OBS = integer + fraction·10⁻⁹ Гц;
- лишние колонки игнорируются;
- ramp-частота содержит start_freq2 modulo 10⁹.

По умолчанию обрабатывается интегрированная орбита. Для самостоятельной проверки измерительной модели есть --trajectory reference. Выбранный источник записан в JSON.

Эпохи передаются двумя слагаемыми double. При вызове CSPICE остаток малой части учитывается через скорость; при интерполяции малые сдвиги времени сохраняются. Это устраняет существенную потерю точности при вычитании больших эпох.

Дата измерения трактуется как середина интервала ODF. Декодированная опорная частота этого набора относится к передающему уровню; в формуле Мойера используется fREF = (880/749)·decoded_REF. Оба соглашения явно записаны в результатах.

Одно экстремальное наблюдение маркируется правилом 100 MAD. Все 12832 исходные строки сохраняются; отдельно приводится статистика по 12831 допустимому наблюдению и по всем строкам. На полном наборе при эталонной орбите RMS около 0.110 Гц; этот результат нельзя заменять меньшей цифрой с пробной выборки.

## Этап 4

Оцениваются шесть поправок к начальному декартову состоянию аппарата. Для каждой оценки заново интегрируется динамическая модель, вычисляются модельный доплер и невязки Observed−Computed.

Используется невзвешенный МНК с демпфированием Левенберга–Марквардта, масштабированием параметров и конечными разностями для производных. Принимаются только шаги, уменьшающие RMS. Каждая попытка записывается в iterations.csv.

--points задаёт приблизительный максимум равномерно выбранных наблюдений; фактическое число записывается в JSON. --fit-hours ограничивает интервал, 0 означает весь доступный интервал. --iterations задаёт предел итераций. Флаг converged записывается отдельно от достижения лимита.

Проверенный расчёт на 179 наблюдениях по всему интервалу: RMS примерно 1.443 → 0.325 Гц. Это результат данной модели на данной выборке, а не обещание точности окончательного навигационного решения. Подробного отдельного условия четвёртого этапа в найденных письмах нет; реализована общая постановка МНК, описанная в первом письме и на доске.

Тропосфера, ионосфера, аппаратурные задержки, приливы и полный релятивистский переход GCRS→BCRS не добавлены как новые требования. Используется ведущий топоцентрический член преобразования времени. Отсутствующие эффекты и различия данных могут оставаться в невязках.

## Проверки и воспроизведение

[VERIFICATION.md](VERIFICATION.md) содержит результаты и команды. CTest проверяет центральное поле, полярные точки, степень 160, порядок RK8, предельный случай EIH, ориентацию, интерполяцию и формат наблюдений/ramp-таблиц.

Сторонняя сверка поля выполнена с SHTOOLS 4.14.1 в 46 неполярных точках; максимум разницы ускорений около 5.21·10⁻¹⁸ км/с². Проверочный скрипт tools/validate_shtools.py не участвует в рабочем C++ расчёте.

Формулы, коэффициенты и выбранные соглашения: [MODEL_SOURCES.md](MODEL_SOURCES.md). Сверка с условиями: [CLASS_NOTES_CHECK.md](CLASS_NOTES_CHECK.md).

Старые каталоги результатов вне results/corrected относятся к предыдущим версиям и не используются как подтверждение исправленной модели.
