# Что задано для третьего этапа и что реализовано

Условие третьего этапа описано в ранее предоставленном письме преподавателя от 23.10.2026. Ниже — техническая выжимка задания без переписки и личных данных участников.

| Пункт задания | Реализация этой копии |
|---|---|
| Ramped Two-way Doppler по Moyer, формула 13-54, стр. 13-36 | `computeDoppler` |
| M2 = 880/749 | Константа коэффициента транспондера |
| Интеграл по процедуре 13.3.2.2.2 | `Ramps::phase`: точное интегрирование линейной частоты по каждому участку, с переходом границ |
| Только data_type_id = 12 | `readObservations` |
| compression_time дано в миллисекундах | По умолчанию `T_c = compression_time * 0.001` секунд |
| Упаковка REF_FREQ | `(high * 16777216 + low) / 1000` Гц |
| Упаковка OBS | `obs_int + obs_frac * 1e-9` Гц |
| Колонки после obs_frac не нужны | Парсер их игнорирует и допускает строку из первых 10 полей |
| Сначала ID принимающей, затем передающей станции | Исправлен порядок чтения полей `rx`, `tx` |
| Упаковка ramp rate | `rate_int + rate_frac * 1e-9` Гц/с |
| Упаковка start frequency | `start_freq_1 * 1e9 + start_freq2 % 1e9 + start_freq3 * 1e-9` Гц |
| Одинаковые dsn_id1 и dsn_id2 в ramp | Проверка при чтении |
| EOP MJD в TAI, TT−TDB из de442t | Используются в новой третьей копии при вычислении положения станции |

## Принятые соглашения и границы проверки

В письме не уточнено, к какой точке интервала относится дата наблюдения. Использована стандартная конвенция ODF: середина интервала накопления. Для запуска и результатов это записано как `TAI midpoint (ODF convention)`.

Есть различие единиц между заданием и исходным стандартом ODF: в ODF поле compression time имеет единицу 0.01 секунды, а преподаватель описал **текстовую выгрузку** в миллисекундах. Поэтому основной запуск следует письму: 500 означает 0.5 секунды. Для явного исследования иной трактовки есть `--count-scale 0.01`. Программа не выбирает масштаб по тому, какой даёт меньшую невязку. Выбранный масштаб записывается в JSON.

Для этого набора декодированная REF_FREQ трактуется как опора на передающем частотном уровне; в формуле Мойера опора на приёмном уровне принимается равной `(880/749) * REF_FREQ`. Это соглашение явно сохранено в JSON. Без согласования уровней частоты возникает систематическое расхождение порядка гигагерца. Сам текст письма не поясняет этот переход между уровнями.

Для самостоятельной проверки измерительной модели координаты аппарата интерполируются из эталонной `msgr_final.bsp`. Это проверка расчёта доплера при заданной траектории, а не итоговая подгонка динамической модели под наблюдения. Подгонка параметров относится к этапу 4.

Тропосфера, ионосфера, аппаратурные задержки и полная релятивистская трансформация положения станции GCRS→BCRS пока не включены. Программа использует ведущий топоцентрический член времени. Статистика невязок сама по себе не доказывает полноту навигационной модели.

## Уточнение ориентира первого этапа

В письме от 13.10 сначала ожидалось около 1700 м без гармоник, около 1000 м с гармониками и 250–300 м после добавления солнечного давления. В письме от 23.10 солнечное давление отменено. Поэтому опубликованный максимум около 982 м для модели с гармониками и без солнечного давления согласуется с ориентиром около 1000 м. Число 250–300 м не является актуальным требованием к варианту без давления.

Первая и вторая накопительные копии сохранены без изменения их исходников. Следует также учитывать различия с первоначальным описанием первого этапа: там упоминались уравнения Эйнштейна–Инфельда–Хоффмана и схема Рунге–Кутты 8-го порядка, а опубликованная динамическая модель использует ньютоновские возмущения и адаптивный Dormand–Prince 5(4). Поле HgM009 вычисляется собственной декартовой реализацией, а не вызовом предоставленного SHTOOLS-модуля; поворот Меркурия берётся из IAU_MERCURY. Эти различия отмечены явно: готовность расчёта доплера не означает автоматического подтверждения всех первоначальных требований к динамике и сдачи всей практики.
