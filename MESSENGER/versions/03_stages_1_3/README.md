# Накопительная версия: этапы 1–3

Копия содержит команды `orbit`, `lighttime`, `doppler` и `selftest`. Этап 3 описан преподавателем: ramped Two-way Doppler по формуле Мойера 13-54 и интегрирование частоты по ramp-таблицам из раздела 13.3.2.2.2.

## Запуск

Общие данные и библиотеки из [релиза common-data-v1](https://github.com/moonyka/KM_labs/releases/tag/common-data-v1) распакуйте в корень репозитория. Повторно загружать архив после получения копии 3 не нужно: используются те же исходные файлы.

В папке этой копии запустите `run.cmd`. Скрипт соберёт программу, выполнит CTest и обработает все наблюдения. Рабочая папка самого расчёта — `MESSENGER`.

В VS Code откройте `KM_labs.code-workspace` в корне репозитория и нажмите F5. Пошаговое объяснение: [RUN_IN_VSCODE.md](../../RUN_IN_VSCODE.md).

После сборки, находясь в `MESSENGER`, можно запускать:

```powershell
.\build\03_stages_1_3\Release\messenger.exe selftest
.\build\03_stages_1_3\Release\messenger.exe orbit
.\build\03_stages_1_3\Release\messenger.exe lighttime
.\build\03_stages_1_3\Release\messenger.exe doppler --out results/my_doppler
```

## Что делает третий этап

1. Читает наблюдения из `obs_4.txt`, выбирает `data_type_id == 12`.
2. Восстанавливает частоты и наблюдаемые значения из составных полей.
3. Переводит время накопления из миллисекунд в секунды: 500 означает 0.5 с.
4. Для начала и конца интервала решает световое время и получает соответствующий интервал передачи.
5. Интегрирует частоту передатчика по кусочно-линейным участкам `ramps_4.txt`, включая переходы через границы участков.
6. Применяет коэффициент 880/749 и получает модельный Doppler; вычисляет разность «наблюдение минус модель».
7. Сохраняет все вычисленные строки, включая отмеченное экстремальное наблюдение. Отдельно выводит статистику с этим значением и без него.

При постоянной опоре на приёмном уровне формула имеет вид:

$$F_2=f_{REF}-\frac{M_2}{T_c}\int_{t_{1s}}^{t_{1e}} f_T(t)\,dt.$$

Для участка `f_T(t)=f_0+\dot f(t-t_0)` интеграл вычисляется аналитически. Если интервал пересекает границу ramp, программа суммирует интегралы отдельных частей.

Важные соглашения: метка наблюдения считается серединой интервала по ODF; REF_FREQ из текстового файла трактуется как опора на передающем уровне, а `f_REF = (880/749) * REF_FREQ`. Координаты аппарата в режиме `doppler` берутся из сплайна эталонной SPK. Это проверка измерительной модели при заданной траектории; динамическая подгонка здесь не выполняется.

## Изменения по исходному письму преподавателя

Подробная сверка: [REQUIREMENTS.md](REQUIREMENTS.md). В этой копии EOP интерполируются по MJD TAI, разность TT−TDB берётся из временной эфемериды `de442t.bsp`, исправлены масштаб времени накопления и порядок ID станций, применяется остаток по модулю 1e9 в составе ramp frequency. Последующие лишние колонки наблюдений игнорируются.

Для специального сравнения со стандартной единицей сырого ODF (0.01 секунды) доступен `--count-scale 0.01`. **Основной результат** получен с миллисекундами согласно письму: `--count-scale 0.001`. Выбранное значение записано в `summary.json`; единицы не подбирались под минимальную невязку.

## Проверки и ограничения

CTest проверяет базовую численную часть и отдельный набор тестов формата наблюдений, миллисекунд, фильтра типа 12, восстановления знака/дробной части, игнорирования лишних полей, модуля частоты и интеграла на стыке ramp. Ошибки покрытия ramp должны приводить к явному отказу вычисления, а не к экстраполяции.

В модели нет тропосферы, ионосферы, аппаратурных задержек и полной релятивистской трансформации положения станции. Успешные тесты и малая часть невязок не означают выполнения всех требований к окончательному навигационному решению. Отличия унаследованной динамической модели от первоначального задания первого этапа отмечены в REQUIREMENTS.md. Первая и вторая опубликованные копии не изменены.
